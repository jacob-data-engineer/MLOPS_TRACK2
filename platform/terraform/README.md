# Track2 YOLO retraining + serving pipeline

Implements the flow from the diagram: **S3 (images) -> SageMaker (YOLO
training) -> S3 (model registry) -> Model Monitor -> Amazon A2I (human
review) -> Endpoint -> Production**.

Fully separate from `SNAIC-JP/Track2`'s own real, already-applied infra
(its `Track2SageMakerExecutionRole` + 4 Model Package Groups) — nothing
here touches that, per explicit choice, so this can't collide with or
destabilize Track2's existing curation/train/register/UAT pipeline for
its (placeholder-model) work.

## Two layers, on purpose

- **`infra/`** (Terraform) — static AWS scaffolding: S3 bucket, ECR repo,
  IAM roles, the Model Package Group, the A2I workteam/human-task-UI/flow
  definition, and the confidence-drift monitor + alarm + Lambda chain.
  **Applied**: run `terraform apply tfplan` from `infra/` (already
  planned — 37 resources, all low-cost: no GPU training, no live endpoint
  yet).
- **`../model_training/src/` + `../model_training/training-container/`**
  (Python/SageMaker SDK) — the actual pipeline logic, kept in its own
  top-level folder outside `terraform/` since none of it is
  Terraform-managed. Can't be static Terraform resources because they all
  need a real trained model's artifact to exist first.

## What's real vs. simplified right now

- **Real**: the 275 hazard images this trains on are the actual images
  from `safety-model-dataset-dev` (not synthetic).
- **Simplified**: those images have **no real bounding-box labels**
  anywhere (checked S3 and the local Label Studio install) — only
  filename category tags (`Helmet`/`Gloves`/`Vehicles`/`FallZone`). Boxes
  are synthetic (a fixed centered region) for now, generated by
  `src/seed_training_data.py`. Same "prove the mechanics, not the model
  quality" precedent Track2's own `DummyClassifier` already sets. Nothing
  downstream needs to change when real annotations exist — swap
  `seed_training_data.py`'s label generation for a real Label Studio
  export and re-run.
- **Not AWS's built-in SageMaker Data Quality Model Monitor**: that
  construct expects tabular/JSON feature data, not raw images — doesn't
  apply to a CV endpoint. Replaced with a small purpose-built Lambda
  (`infra/lambda_src/confidence_monitor.py`) that reads the endpoint's
  captured input/output, tracks mean prediction confidence against a
  baseline, and feeds the same CloudWatch-alarm -> SNS -> A2I chain a
  real Model Monitor would.

## Human approval gate

Mirrors Track2's own `docs/production_promotion.md`: `RegisterModel`
always registers at `ModelApprovalStatus=PendingManualApproval`.
`deploy_endpoint.py` refuses to deploy anything that isn't `Approved`.
Nothing in the pipeline itself ever calls `approve_model.py` — a person
always has to run it explicitly.

## Running it end to end

```sh
# 1. Apply the Terraform scaffolding (once)
cd infra && terraform apply tfplan
terraform output   # note: pipeline_bucket, sagemaker_execution_role_arn, etc.

# 2. Invite yourself (and later, teammates) into the A2I review portal
cd ../scripts && ./add_reviewer.sh 2570475@sit.singaporetech.edu.sg

# 3. Build and push the training + serving containers
cd ../../model_training/training-container && ./build_and_push.sh

# 4. Seed the dataset (real images, synthetic boxes) into the pipeline bucket
cd ../src && pip install -r requirements.txt
python seed_training_data.py

# 5. Run the training pipeline (needs a GPU-capable environment; the
#    SageMaker SDK's own local dependencies are fine on Windows here,
#    unlike Track2's WSL requirement — this pipeline has no local
#    Windows-vs-Linux repack step)
python run_pipeline.py

# 6. Look at the results, then decide — a person, not the pipeline
python approve_model.py --list
python approve_model.py <model-package-arn>

# 7. Deploy the approved model to the serverless endpoint
python deploy_endpoint.py <model-package-arn>

# 8. The confidence_monitor Lambda now runs every 15 minutes against real
#    endpoint traffic; a confidence drop over the drift threshold writes
#    a violations report and (via the CloudWatch alarm + SNS) triggers a
#    human review task for whoever's in the A2I workforce.
```

## Diagram -> what's actually built

`src/` and `training-container/` below both live at `../model_training/`
(one level up from this `terraform/` folder), not inside it.

| Diagram stage | This repo |
|---|---|
| Amazon S3 (B1) — image repo | `infra/s3.tf` (`images/dataset/` prefix), populated by `src/seed_training_data.py` |
| SageMaker — YOLO training | `training-container/` (Dockerfile + train.py), `src/pipeline_definition.py`'s `TrainingStep` |
| Amazon S3 (B1) — model registry | `infra/sagemaker.tf`'s Model Package Group (`track2-yolo-models`) + `training-output/` prefix |
| Model Monitor | `infra/lambda_src/confidence_monitor.py` (custom, not AWS's built-in Data Quality Monitor — see above) |
| Amazon A2I | `infra/sagemaker.tf` (workforce/workteam/human-task-UI/flow-definition), `infra/lambda_src/trigger_review.py` |
| Endpoints | `src/deploy_endpoint.py` — serverless, gated on `ModelApprovalStatus=Approved` |
| Production | the live endpoint (`track2-yolo-endpoint`), with data capture feeding the monitor loop back at the top |
